# Bug: Re-transcribe Dialog Hot Loop and Appearance Control Desync

- **Date:** 2026-11-17
- **What was asked / symptom:**
  1. The `ReTranscribeDialog` flickers continuously for over a minute upon opening, and the entire UI thread becomes completely unresponsive (buttons, tabs, inputs unclickable).
  2. The appearance segmented control in the top-right header displayed "Light" while the app's visual theme was actually dark.
- **Root cause:**
  1. **Hot Loop in ReTranscribeDialog:**
     `ReTranscribeDialog` bound `<Configure>` on `self` (`self.bind("<Configure>", self._on_configure)`). In Tkinter, binding on a `Toplevel` without checking `if e.widget != self: return` causes the event handler to intercept every `<Configure>` generated by any descendant widget (entries, frames, buttons, canvas). Inside `_on_configure`, it executed `self.canvas.itemconfig(self.scroll_win, width=e.width)`. Resizing the canvas item resized the inner frame and children, which immediately triggered new `<Configure>` events, causing an uncontrolled re-entrant recursion loop firing at **564.7 events/second** (5,647 events in 10 seconds), starving the Tkinter message loop.
  2. **Appearance Control Desync:**
     When the application launched, `gui/app.py` initialized `_theme_mode` (default `"system"` or saved user preference). However, in `Stage3Tab.__init__`, a redundant call `theme.apply_global_theme(self)` was made without passing the user's configured theme mode or scale. Because default was `"system"`, `apply_global_theme` detected Windows OS dark mode from the registry, switching TTK styles and module-level color constants to dark mode while `app.py`'s segmented control variable still reflected `"light"`.
- **What was changed / fix:**
  1. **Dialog Loop Elimination:**
     - Added `if e.widget != self: return` guard to `ReTranscribeDialog._on_configure`.
     - Added width difference threshold (`if abs(new_w - self._last_dialog_width) <= 1: return`) and cached `self._last_dialog_width`.
     - Added centralized `theme.style_toplevel(self)` and `theme.center_dialog(self, parent, 720, 620)` helpers.
     - Event rate dropped from **564.7 events/sec** to **31 initial setup events**, with zero subsequent steady-state events and zero UI freezes.
  2. **Theme Desync Elimination & Idempotency:**
     - Removed redundant `theme.apply_global_theme(self)` call inside `Stage3Tab.__init__`.
     - Established `gui/app.py` as the single authoritative source of truth for theme state, passing `scale`, `density`, and `theme_mode` centrally.
     - Added `_LAST_APPLIED_STATE` cache and `_IN_APPLY_THEME` re-entrancy lock in `gui/theme.py` so identical theme requests are no-ops.
     - Added rate-limiting loop guard in `apply_global_theme` ($\ge 6$ calls/second threshold) that raises a warning and suppresses runaway loops while allowing `force=True` test overrides.
     - Updated `SegmentedControl._refresh()` to dynamically show the resolved system state (e.g., `System (Dark)` or `System (Light)`) when in system mode.
- **Files touched:**
  - `gui/stage3_tab.py`: Added widget check and width diff threshold to `ReTranscribeDialog`; removed redundant `apply_global_theme` in `Stage3Tab.__init__`.
  - `gui/theme.py`: Added `_LAST_APPLIED_STATE`, `_IN_APPLY_THEME`, loop rate-limiter, `style_toplevel`, `center_dialog`, and resolved segmented control labels.
  - `gui/app.py`: Centralized initial `_apply_theme()` call and clean teardown in `destroy()`.
  - `tests/test_theme_lifecycle_and_inputs.py`: Added automated regression tests for dialog responsiveness, 0 steady-state calls, and segmented control resolution.
- **How it was verified:**
  - Ran `tests/test_theme_lifecycle_and_inputs.py`: All 7 unit tests passed. Measured probe UI jitter on active dialog: worst-case 14.57ms, 0 frames blocked > 100ms.
  - Captured dark mode dialog screenshot in `scratch/theme_review/retranscribe_dialog_dark.png` verifying clean rendering, centered placement, and immediate input readiness.
